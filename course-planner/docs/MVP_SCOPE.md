# MVP 功能範圍與驗收基準

## 已交付且可驗證

- 校方公開課程 API 的受控同步、版本化靜態快照、schema 驗證與快照差異摘要。
- 明確的快照範圍揭露；目前部署的是 1151 學期「微積分」課名篩選的 48 門課程，並非全校課程清單。
- 依課名、課號、教師、最低學分、必選修與上課日搜尋，顯示學分、時段、教室；加入／移出候選課表、學分加總、衝堂提示與每週格狀課表。
- 候選課表僅儲存在使用者的瀏覽器，會隨新快照排除失效課號，並可清除。
- 主系、雙主修、輔系共用的規則 schema、進度計算與來源／審核狀態閘門；目前網站刻意只使用 `demo` 規則。
- GitHub Actions 執行資料驗證、單元測試、lint 與靜態建置，並部署至 GitHub Pages。

## 待人工資料審核後交付

- 指定入學年度、學制與系所後，依官方原始表格建立並覆核正式主系、雙主修與輔系 requirement set。
- 依使用情境擴充課程快照範圍（系所、必修群組或全學期）。每一份快照都必須先 dry run、檢視差異、通過 schema，才可寫入版本。

## 不在 MVP 範圍

- 校務 SSO、正式選課送出、成績讀取或儲存；此專案不收集密碼、成績或選課紀錄。
- 課程評價、社群留言、交易或錢包功能；這些需要獨立的社群治理、授權與安全設計。

完整的資料匯入規範見 [REQUIREMENT_REVIEW.md](REQUIREMENT_REVIEW.md)，每次功能與驗證紀錄見 [PROGRESS.md](PROGRESS.md)。
